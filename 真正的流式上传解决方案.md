# 真正的流式上传解决方案

## 问题定义

### 什么是"真正的流式上传"？

**定义**：
- 数据到达服务器时**立即**写入磁盘
- 不需要等待完整文件上传
- 磁盘文件大小**持续增长**
- 内存占用**恒定**

### 为什么Multipart不是真正的流式？

```java
// Multipart 流程
客户端上传
  ↓ (等待完整上传)
Mono<FilePart> 触发  ← 这里才开始处理！
  ↓
写入目标文件
```

**关键**：必须等待 `Mono<FilePart>` 发出信号，而这要等完整上传。

## 解决方案

### 核心思路

**绕过 FilePart，直接消费原始数据流！**

```java
// 不使用 FilePart
@RequestPart("file") Mono<FilePart> filePart  // ❌ 会等待

// 直接消费数据流
@RequestBody Flux<DataBuffer> body  // ✅ 实时处理
```

### 完整实现

```java
@PostMapping(value = "/upload-video-raw", 
             consumes = MediaType.APPLICATION_OCTET_STREAM_VALUE)
public Mono<ResponseEntity<Map<String, Object>>> uploadVideoRaw(
        @RequestHeader("X-Filename") String filename,
        @RequestHeader(value = "X-Content-Type", required = false) String contentTypeHeader,
        @RequestParam(value = "forceInterval", required = false) String forceIntervalStr,
        @RequestBody Flux<DataBuffer> dataBufferFlux) {
    
    // 解析参数
    int forceInterval = parseForceInterval(forceIntervalStr);
    
    // 生成文件路径
    String videoDirPath = System.getProperty("user.home") + "/Movies/uploads/";
    String timestamp = LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMdd_HHmmss"));
    String newFilename = "video_" + timestamp + getExtension(filename);
    Path path = Paths.get(videoDirPath + newFilename);
    
    logger.info("📦 接收到视频上传请求 | 文件名: {}", filename);
    
    // 创建目录
    return Mono.fromCallable(() -> {
        File dir = new File(videoDirPath);
        if (!dir.exists()) {
            dir.mkdirs();
        }
        return path;
    }).subscribeOn(Schedulers.boundedElastic())
    
    // 流式写入文件
    .flatMap(filePath -> {
        return Mono.using(
            // 资源创建：打开文件通道
            () -> {
                try {
                    return AsynchronousFileChannel.open(
                        filePath,
                        StandardOpenOption.WRITE,
                        StandardOpenOption.CREATE,
                        StandardOpenOption.TRUNCATE_EXISTING
                    );
                } catch (IOException e) {
                    throw new RuntimeException("无法打开文件: " + e.getMessage(), e);
                }
            },
            
            // 资源使用：流式写入
            channel -> {
                AtomicLong position = new AtomicLong(0);
                AtomicLong chunkCount = new AtomicLong(0);
                AtomicLong lastForceChunk = new AtomicLong(0);
                long startTime = System.currentTimeMillis();
                
                return dataBufferFlux
                    .publishOn(Schedulers.boundedElastic())  // 在阻塞调度器上处理
                    .doOnNext(dataBuffer -> {
                        try {
                            long currentPosition = position.getAndAdd(dataBuffer.readableByteCount());
                            chunkCount.incrementAndGet();
                            
                            // 写入数据
                            ByteBuffer byteBuffer = dataBuffer.asByteBuffer();
                            channel.write(byteBuffer, currentPosition).get();  // 阻塞等待写入完成
                            
                            // 释放DataBuffer
                            DataBufferUtils.release(dataBuffer);
                            
                            // 定期刷新到磁盘
                            if (forceInterval > 0 && 
                                chunkCount.get() - lastForceChunk.get() >= forceInterval) {
                                channel.force(true);  // 强制刷新
                                lastForceChunk.set(chunkCount.get());
                                
                                long elapsed = System.currentTimeMillis() - startTime;
                                double speed = (double) position.get() / (1024 * 1024) / 
                                              (elapsed / 1000.0);
                                
                                logger.info("💾 视频已刷新到磁盘 | 数据块: {} | 磁盘大小: {:.2f} MB | 速度: {:.1f} MB/s",
                                    chunkCount.get(), 
                                    position.get() / (1024.0 * 1024.0), 
                                    speed);
                            }
                        } catch (Exception e) {
                            throw new RuntimeException("写入文件失败: " + e.getMessage(), e);
                        }
                    })
                    .then(Mono.fromCallable(() -> {
                        // 最后一次强制刷新
                        try {
                            channel.force(true);
                            logger.info("✅ 视频最终刷新完成，总数据块: {}", chunkCount.get());
                        } catch (IOException e) {
                            logger.error("最终刷新失败", e);
                        }
                        
                        // 构建响应
                        Map<String, Object> result = new HashMap<>();
                        result.put("filename", newFilename);
                        result.put("size", position.get());
                        result.put("path", filePath.toString());
                        result.put("chunks", chunkCount.get());
                        result.put("message", "视频上传成功");
                        
                        return ResponseEntity.ok(result);
                    }));
            },
            
            // 资源清理：关闭文件通道
            channel -> {
                try {
                    channel.close();
                } catch (IOException e) {
                    logger.error("关闭文件通道失败", e);
                }
            }
        );
    })
    
    // 错误处理
    .onErrorResume(e -> {
        logger.error("视频上传失败", e);
        Map<String, Object> result = new HashMap<>();
        result.put("message", "上传失败: " + e.getMessage());
        return Mono.just(ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(result));
    });
}
```

## 关键技术点

### 1. 使用 `application/octet-stream`

```java
consumes = MediaType.APPLICATION_OCTET_STREAM_VALUE
```

**原因**：
- 不使用 multipart/form-data
- 直接传输原始二进制数据
- 没有boundary解析延迟

### 2. 元数据通过Header传递

```java
@RequestHeader("X-Filename") String filename
@RequestHeader("X-Content-Type") String contentType
@RequestHeader("X-Force-Interval") String forceInterval
```

**原因**：
- Multipart的元数据在part header中
- Raw Binary没有part，需要自定义header

### 3. 直接消费 `Flux<DataBuffer>`

```java
@RequestBody Flux<DataBuffer> dataBufferFlux
```

**关键**：
- 绕过FilePart
- 数据到达立即处理
- 真正的流式！

### 4. 使用 `AsynchronousFileChannel`

```java
AsynchronousFileChannel channel = AsynchronousFileChannel.open(
    path,
    StandardOpenOption.WRITE,
    StandardOpenOption.CREATE
);
```

**优势**：
- 异步文件I/O
- 支持指定位置写入
- 高性能

### 5. 定期强制刷新

```java
if (chunkCount.get() % forceInterval == 0) {
    channel.force(true);  // 强制刷新到磁盘
}
```

**作用**：
- 确保数据真正写入磁盘
- 防止断电丢失数据
- 可配置刷新频率

### 6. 在 boundedElastic 调度器上处理

```java
.publishOn(Schedulers.boundedElastic())
```

**原因**：
- 文件写入是阻塞操作
- 不能阻塞事件循环线程
- boundedElastic适合I/O操作

## 性能对比

### Multipart方式

```
客户端上传: [0-10s]
服务端日志: [10s] ⏰ FilePart到达
文件创建:   [10s] 一次性写入
```

### Raw Binary方式（本方案）

```
客户端上传: [0-10s]
服务端日志: [0.05s] 📦 接收到请求
           [1s] 💾 已刷新
           [2s] 💾 已刷新
           ...
文件创建:   [0.05s] 立即创建，持续增长
```

**关键差异**：
- Multipart：延迟10秒
- Raw Binary：延迟50ms
- **快200倍！**

### iOS Swift

```swift
func uploadVideoRaw(fileURL: URL) {
    var request = URLRequest(url: URL(string: "http://server/image/upload-video-raw")!)
    request.httpMethod = "POST"
    
    // 设置Content-Type
    request.setValue("application/octet-stream", forHTTPHeaderField: "Content-Type")
    
    // 设置自定义Header
    request.setValue("video.mp4", forHTTPHeaderField: "X-Filename")
    request.setValue("video/mp4", forHTTPHeaderField: "X-Content-Type")
    request.setValue("500", forHTTPHeaderField: "X-Force-Interval")
    
    // 使用流式上传
    request.httpBodyStream = InputStream(url: fileURL)
    
    let task = URLSession.shared.uploadTask(with: request, fromFile: fileURL) { data, response, error in
        if let error = error {
            print("上传失败: \(error)")
            return
        }
        
        if let data = data {
            print("上传成功: \(String(data: data, encoding: .utf8) ?? "")")
        }
    }
    
    task.resume()
}
```

## 注意事项

### 1. forceInterval 参数调优

```java
forceInterval = 0     // 不强制刷新（最快，但风险高）
forceInterval = 100   // 高频刷新（最安全，性能稍低）
forceInterval = 500   // 推荐值（平衡性能和安全）
forceInterval = 1000  // 低频刷新（性能优先）
```

### 2. 内存释放

```java
DataBufferUtils.release(dataBuffer);  // 必须手动释放！
```

**原因**：
- DataBuffer使用堆外内存
- 不释放会导致内存泄漏

### 3. 错误处理

```java
.onErrorResume(e -> {
    logger.error("上传失败", e);
    // 清理已写入的文件
    Files.deleteIfExists(filePath);

})
```

```java
// 上传完成后验证
long expectedSize = ...;
long actualSize = Files.size(filePath);
if (actualSize != expectedSize) {
    throw new RuntimeException("文件大小不匹配");
}
```

## 总结

### 核心要点

1. **绕过Multipart**
   - 使用 `application/octet-stream`
   - 直接消费 `Flux<DataBuffer>`

2. **元数据通过Header**
   - X-Filename
   - X-Content-Type
   - X-Force-Interval

3. **使用 AsynchronousFileChannel**
   - 异步文件I/O
   - 指定位置写入
   - 定期强制刷新

4. **在正确的调度器上处理**
   - publishOn(Schedulers.boundedElastic())
   - 避免阻塞事件循环

### 适用场景

- ✅ 大文件上传（>100MB）
- ✅ 需要实时进度
- ✅ 可以修改客户端
- ✅ 追求极致性能

### 不适用场景

- ❌ 无法修改客户端（iOS标准上传）
- ❌ 小文件（<10MB，Multipart够用）
- ❌ 需要标准兼容性
